## 1. Plugin Architecture

| Decision | Choice |
|----------|--------|
| Architecture | Standalone plugin, own vault |
| Vault location | `~/story-vault/`, configurable |
| Plugin config | Hermes plugin config |
| Plugin registration | Standard Hermes plugin API |
| Multiple projects | One vault, multiple project folders |
| obsidian-vault integration | None — borrow concepts, not code |

**Borrowed concepts** (ideas, not code):
- Three-stage retrieval (index → target → load)
- Frontmatter → body mapping
- Standard `##` sections for targeting
- Always-loaded project index
- Zero-dependency regex section parser

**Not borrowed**:
- `.vault/config.yaml` schema DSL → Python validation
- `obsidian_*` tools → raw file I/O + our own tools
- Grant/role system → single-user, no grants needed
- `INDEX.md` generation → our own if needed

## 2. Vault Structure

```
~/story-vault/                          # Configurable
├── .story/
│   ├── index.yaml                      # Project graph (always-loaded)
│   ├── memory.md                       # Story Memory (continuity map)
│   └── history.md                      # Edit history (gitignored)
└── projects/
    └── <project-slug>/
        ├── project.md                  # Project metadata
        ├── title-page.md
        ├── synopsis.md
        ├── treatment.md                # Ordered outline, one paragraph per beat
        ├── screenplay.md               # Fountain syntax
        ├── characters/
        │   ├── mara.md
        │   └── detective-oak.md
        ├── locations/
        │   └── kitchen.md
        ├── worlds/
        │   └── gilead.md
        └── plots/
            └── main-plot.md
```

**No `_index.md` files** — YAGNI, `.story/index.yaml` is the source of truth.

**No `.vault/` folder** — using `.story/` only.

## 5. Entity Schemas

### Character (`characters/<slug>.md`)

**Required fields** (index needs these):
```yaml
name: string
story_role: string              # Protagonist, Antagonist, Supporting, Minor, Cameo
one_sentence: string
sections: string[]              # Auto-generated by index
```

**Optional fields**:
```yaml
age: string                     # "34" or "30s"
relationships:
  - id: slug
    feeling: string
scenes: string[]                # Scene headings
goals:
  short: string
  long: string
knowledge: string[]
```

### Location (`locations/<slug>.md`)

**Required**:
```yaml
name: string
one_sentence: string
sections: string[]
```

**Optional**:
```yaml
scenes: string[]
```

### World (`worlds/<slug>.md`)

**Required**:
```yaml
name: string
one_sentence: string
sections: string[]
```

**Optional**:
```yaml
rules: string[]
```

### Plot (`plots/<slug>.md`)

**Required**:
```yaml
name: string
status: string                  # active, resolved, abandoned
sections: string[]
```

**Optional**:
```yaml
setups: string[]                # Scene headings
payoffs: string[]               # Scene headings
characters: string[]
one_sentence: string
```

### Project (`project.md`)

**Required**:
```yaml
name: string
logline: string
```

**Optional**:
```yaml
genre: string
setting: string
```

### Scene (in `.story/index.yaml`)

Scenes are NOT separate notes. Parsed from `screenplay.md`:

```yaml
scenes:
  - id: 1                       # Sequential number (regenerated on each index update)
    heading: "INT. MARA'S APARTMENT - NIGHT"
    characters: [mara]           # Extracted from dialogue cues via screenplay-tools
    locations: []                # Extracted from heading
    plots: [brother-investigation]
```

## 6. Validation Rules

```python
REQUIRED_FIELDS = {
    "character": ["name", "story_role", "one_sentence", "sections"],
    "location": ["name", "one_sentence", "sections"],
    "world": ["name", "one_sentence", "sections"],
    "plot": ["name", "status", "sections"],
    "project": ["name", "logline"],
}

VALID_ROLES = ["Protagonist", "Antagonist", "Supporting", "Minor", "Cameo"]
VALID_STATUSES = ["active", "resolved", "abandoned"]
```

`sections` field is **auto-generated by the index generator** (parses `##` headings, writes back to frontmatter).

---

## 7. Screenplay Format

| Decision | Choice |
|----------|--------|
| Fountain parsing | `screenplay-tools` library (Parser + Writer) |
| Scene numbering | Sequential, regenerated on each index update |
| Character extraction | From dialogue via `screenplay-tools` Parser |
| Screenplay editing | `screenplay-tools` Writer for round-trip |
| Treatment/synopsis format | Plain Markdown, no frontmatter |

**Conflict resolution**: Frontmatter is source of truth for character/scene membership. Screenplay extraction is supplementary.

---

## 8. Standard Body Sections

Enforce these `##` headings so the index can target retrieval by name:

**Character**: `Personality`, `Background`, `Voice`, `Greatest Fear`, `Secrets`, `Arc`, `Relationships`, `Goals`, `Plot Involvement`

**Location**: `Description`, `History`, `Scenes`

**World**: `Description`, `History`, `Conflict`

**Plot**: `Summary`, `Obstacles`, `Stakes`

---

## 9. Cross-Reference System

Plain slugs in frontmatter, validated by index generator. Wikilinks in body prose (for readability) but not required.

```yaml
characters:
  - mara
  - detective-oak
```

Index generator warns on broken references.
