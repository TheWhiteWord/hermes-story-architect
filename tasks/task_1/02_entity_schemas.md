# Subtask: Entity Schema Design — DECIDED

> Define the frontmatter schemas for all entity types. Python-defined, not config-driven.

---

## Key decisions

| # | Decision | Choice | Why |
|---|----------|--------|-----|
| 1 | Character schema richness | Layered (required + optional) | Index needs specific labels; writers add depth as needed |
| 2 | `story_role` vocabulary | Closed (Protagonist, Antagonist, Supporting, Minor, etc.) | Enables filtering by role |
| 3 | `scenes` storage format | Full headings ("INT. KITCHEN - NIGHT") | Stable across renumbering; human-readable |
| 4 | Scene representation | Index-only, parsed from `screenplay.md` | YAGNI — no separate notes |
| 5 | Plot status vocabulary | Closed (active, resolved, abandoned) | Enables filtering by status |
| 6 | Cross-reference format | Plain slugs, validated by index generator | Simple, validated at index time |
| 7 | Extra STARC fields | Exclude (nickname, family, motivation, etc.) | Writers can add to body; not needed for index |

## Schema definitions

### Character (`characters/<slug>.md`)

**Required fields** (index needs these):
```yaml
name: string                    # Display name
story_role: string              # Protagonist, Antagonist, Supporting, Minor
one_sentence: string            # Index label
sections: string[]              # Available ## sections (auto-generated by index)
```

**Optional fields** (writers add as needed):
```yaml
age: string                     # "34" or "30s" — flexible
relationships:                  # List of objects
  - id: slug                    # References another character
    feeling: string             # One-line description
scenes: string[]                # Scene headings this character appears in
goals:
  short: string                 # What they want now
  long: string                  # What they want ultimately
knowledge: string[]             # Facts they know (for continuity tracking)
```

**STARC fields excluded**: nickname, family, personality (in body), motivation (in body), moral (in body), greatest_fear (in body), secrets (in body), initial_beliefs, changed_beliefs, plot_involvement (in body), conflict (in body), speech (in Voice section).

These are all better captured in standard body sections where the prose gives them depth. The index only needs the labels.

### Location (`locations/<slug>.md`)

**Required fields**:
```yaml
name: string
one_sentence: string
sections: string[]
```

**Optional fields**:
```yaml
scenes: string[]                # Scene headings where this location appears
```

**No extra fields needed** — locations are simple. Sensory details, history, purpose all live in body sections.

### World (`worlds/<slug>.md`)

**Required fields**:
```yaml
name: string
one_sentence: string
sections: string[]
```

**Optional fields**:
```yaml
rules: string[]                 # World rules (water rationing, etc.)
```

**No scenes field** — worlds appear in plots, not directly in scenes.

### Plot (`plots/<slug>.md`)

**Required fields**:
```yaml
name: string
status: string                  # active, resolved, abandoned
sections: string[]
```

**Optional fields**:
```yaml
setups: string[]                # Scene headings where plot is established
payoffs: string[]               # Scene headings where plot resolves
characters: string[]            # Character slugs involved
one_sentence: string            # Index label
```

### Project (`project.md`)

**Required fields**:
```yaml
name: string
logline: string
```

**Optional fields**:
```yaml
genre: string
setting: string
```

**No count fields** — scene_count, character_count, etc. are derived from the index.

### Scene (in `.story/index.yaml`)

Scenes are NOT separate notes. They're entries in the index, parsed from `screenplay.md`:

```yaml
scenes:
  - id: 1                       # Sequential number (regenerated on each index update)
    heading: "INT. MARA'S APARTMENT - NIGHT"
    characters: [mara]           # Extracted from dialogue cues
    locations: []                # Extracted from heading ("INT. KITCHEN" → kitchen)
    plots: [brother-investigation]  # From frontmatter cross-reference
```

## Validation rules

```python
REQUIRED_FIELDS = {
    "character": ["name", "story_role", "one_sentence", "sections"],
    "location": ["name", "one_sentence", "sections"],
    "world": ["name", "one_sentence", "sections"],
    "plot": ["name", "status", "sections"],
    "project": ["name", "logline"],
}

VALID_ROLES = ["Protagonist", "Antagonist", "Supporting", "Minor", "Cameo"]
VALID_STATUSES = ["active", "resolved", "abandoned"]

def validate_entity(entity_type: str, frontmatter: dict) -> list[str]:
    """Return list of validation errors (empty = valid)."""
    errors = []
    
    # Check required fields
    for field in REQUIRED_FIELDS.get(entity_type, []):
        if field not in frontmatter:
            errors.append(f"Missing required field: {field}")
    
    # Check vocabulary
    if entity_type == "character" and "story_role" in frontmatter:
        if frontmatter["story_role"] not in VALID_ROLES:
            errors.append(f"Invalid story_role: {frontmatter['story_role']}")
    
    if entity_type == "plot" and "status" in frontmatter:
        if frontmatter["status"] not in VALID_STATUSES:
            errors.append(f"Invalid status: {frontmatter['status']}")
    
    # Check cross-references exist (if index is available)
    if "characters" in frontmatter:
        for char_id in frontmatter["characters"]:
            if not entity_exists(char_id, "character"):
                errors.append(f"Referenced character not found: {char_id}")
    
    if "relationships" in frontmatter:
        for rel in frontmatter["relationships"]:
            if not entity_exists(rel["id"], "character"):
                errors.append(f"Referenced character not found: {rel['id']}")
    
    return errors
```

## Sections field

The `sections` field is **auto-generated by the index generator**, not manually maintained. The index generator:
1. Parses each note's body for `##` headings
2. Writes the list back to frontmatter's `sections` field
3. This keeps the index in sync with the actual content
