## 1. What This Phase Does

Produces **two artifacts** from `story_index`:

1. **Main index** (`.story/index.yaml`) — scenes come from files only (`scenes/*.md`)
2. **Structure index** (`.story/structure-index.yaml`) — dramatic metadata for structural analysis

**End state of Phase 2:**
- `index["scenes"]` contains only file scenes — no screenplay merge
- Character/location `scenes` cross-references built from file scenes only
- `.story/structure-index.yaml` generated alongside main index
- `story_index` regenerates both files; `story_create`/`story_edit` trigger full rebuild

---

## 2. The Clarification

> "Screenplay import is a one-time setup operation. You import to create scene files, or you build manually. They don't coexist as dual sources. When screenplay reintegration comes, it adapts to this architecture — creates files, then it's done."

**Consequence:** Scenes = files. Period. The screenplay is a document in the project, not a scene source. The dashboard's screenplay stats (`_compute_screenplay_stats`) read `screenplay.fountain` directly — they never needed scenes from the index.

This eliminates the `source` field from Phase 2 entirely. Simpler.

## 3. RESEARCH FINDINGS

### 3.1 Current `generate_index()` Scene Flow (Phase 1)

```
screenplay_path = project_path / "screenplay.fountain"
if screenplay_path.exists():
    raw_scenes = extract_scenes(screenplay_path.read_text())
    scenes = [/* matched chars/locs, numeric ids */]
    index["scenes"] = scenes + file_scenes    ← MERGE: mixed types!
else:
    index["scenes"] = file_scenes
```

The merge creates a mixed list: screenplay scenes (numeric `id`, thin shape, no `sequence_id`/`act_id`) alongside file scenes (slug `id`, full shape). Character/location `scenes` enrichment then iterates this mixed list.

### 3.2 What Currently Depends on `index["scenes"]`

| Consumer | What it uses | Impact of file-only scenes |
|----------|--------------|---------------------------|
| `_enrich_cross_references()` | Builds char/loc `scenes` lists | Cleaner — only file scenes |
| `_enrich_structure()` | `sequence.scenes_list`, etc. | Already only checks `sequence_id`/`act_id` — screenplay scenes never had those, so no change |
| `_enrich_scenes_with_plots()` | Reverse-lookup plots onto scenes | Already uses `scene_id` matching — screenplay scenes never matched plots, no change |
| `_validate_index()` | Cross-reference validation | Screenplay scenes had no `sequence_id`/`act_id` — fewer false-positive warnings |
| Dashboard (`story-dashboard.html`) | Reads `window.__STORY_DATA__` | Dashboard reads `screenplay.fountain` directly for screenplay stats; entity panels use index |
| `story_load` | Reports scene count | Accurate: only real scenes counted |

**Verdict:** No consumer breaks. The dashboard's screenplay features use `_compute_screenplay_stats()` which reads the screenplay file directly — it never depended on `index["scenes"]`.

### 3.3 Renaming

`_enrich_from_screenplay()` → `_enrich_cross_references()`. The current name is wrong: it enriches character/location scenes from the scenes list. Once scenes are file-only, the name becomes even more misleading.

## 4. Decisions Made

### 4.1 Scenes = Files Only

**Decision:** `index["scenes"]` = `_parse_entities(project_path / "scenes", "scene")`. No screenplay merge.

**Rationale:** Per user clarification. Screenplay integration is a future one-time import that creates files. No dual sources, no `source` field, no mixed-type lists.

### 4.2 Structure Index Sidecar

**Decision:** Separate file `.story/structure-index.yaml`. Chosen by user.

### 4.3 Structure Index Schema

```yaml
# .story/structure-index.yaml — regenerated by story_index
scenes:
  - id: mara-discovers-files
    value: Trust
    value_open: positive
    value_close: negative
    conflict_levels: [inner, personal]
    dramatic_role: climax
    is_inciting_incident: false
    is_sequence_climax: true
    is_act_climax: false
    is_story_climax: false
    arc_beat_refs: []

sequences:
  - id: seq-inciting-discovery
    value: Trust
    value_open: positive
    value_close: negative
    climax_scene_id: mara-discovers-files

acts:
  - id: act-1
    value: Trust
    value_open: positive
    value_close: negative
    climax_scene_id: mara-discovers-files
```

### 4.4 `arc_beat_refs` Forward Compatibility

**Decision:** Include `arc_beat_refs: []` on every scene entry in structure index.

**Rationale:** Avoids schema migration when the arc system arrives. Empty list = no-op.

### 4.5 Regeneration Strategy

**Decision:** Full rebuild on every `story_index` call. Phase 3 adds lightweight updates via `story_structural edit`.

### 4.6 Strip Dramatic Metadata from Main Index Scenes

**Decision:** Main index scene entries contain ONLY navigation fields per proposal §6. Dramatic metadata (`value`, `value_open`, `value_close`, `conflict_levels`, `dramatic_role`, `is_*_climax`) is stripped.

**Rationale:** With 90+ scenes, these fields become significant context noise for the LLM. The entire purpose of the structure index is to be the single query target for dramatic metadata. If the main index duplicates it, the structure index is pointless overhead.

**Implementation:** A pure filter function in `core/index.py`:

```python
NAVIGATION_SCENE_FIELDS = frozenset([
    "id", "type", "title", "order", "status",
    "sequence_id", "act_id", "heading", "characters",
    "plots", "location", "sections",
])

def _strip_scene_for_navigation(scene: dict) -> dict:
    """Return a scene entry with only navigation fields for the main index."""
    return {k: v for k, v in scene.items() if k in NAVIGATION_SCENE_FIELDS}
```

Applied in `generate_index()`:
```python
index["scenes"] = [_strip_scene_for_navigation(s) for s in file_scenes]
```

**Result:** ~6 lines per scene instead of ~16. For 90 scenes: ~540 lines vs ~1440 lines.

### 4.7 Add Count Fields to Sequence/Act Entries

**Decision:** Add `scene_count` to sequences, `sequence_count` and `scene_count` to acts. Computed in `_enrich_structure()`.

**Rationale:** The UI already digests `scene_count` (from `_compute_screenplay_stats`). These counts are small, stable, and useful for dashboard stats panels in Phase 4.

**Implementation:** In `_enrich_structure()`, after building `scenes_list`:

```python
seq["scene_count"] = len(seq["scenes_list"])
# ...
act["sequence_count"] = len(act["sequences_list"])
act["scene_count"] = len(act["scenes_list"])
```

def generate_structure_index(index: dict) -> dict:
    """Generate the structure index sidecar from the main index.
    
    Only file scenes have dramatic metadata.
    """
    return {
        "scenes": [
            {
                "id": scene["id"],
                "value": scene.get("value", ""),
                "value_open": scene.get("value_open", ""),
                "value_close": scene.get("value_close", ""),
                "conflict_levels": scene.get("conflict_levels", []),
                "dramatic_role": scene.get("dramatic_role", ""),
                "is_inciting_incident": bool(scene.get("is_inciting_incident", False)),
                "is_sequence_climax": bool(scene.get("is_sequence_climax", False)),
                "is_act_climax": bool(scene.get("is_act_climax", False)),
                "is_story_climax": bool(scene.get("is_story_climax", False)),
                "arc_beat_refs": [],
            }
            for scene in index.get("scenes", [])
        ],
        "sequences": [
            {
                "id": seq["id"],
                "value": seq.get("value", ""),
                "value_open": seq.get("value_open", ""),
                "value_close": seq.get("value_close", ""),
                "climax_scene_id": seq.get("climax_scene_id", ""),
            }
            for seq in index.get("sequences", [])
        ],
        "acts": [
            {
                "id": act["id"],
                "value": act.get("value", ""),
                "value_open": act.get("value_open", ""),
                "value_close": act.get("value_close", ""),
                "climax_scene_id": act.get("climax_scene_id", ""),

### 6.3 `write_structure_index()` and `refresh_index()`

```python
def write_structure_index(structure_index: dict, output_path: Path) -> None:
    """Write structure index to YAML."""
    with open(output_path, 'w') as f:
        yaml.dump(structure_index, f, default_flow_style=False, sort_keys=False, allow_unicode=True)


def refresh_index(project_path: Path) -> None:
    """Regenerate and write the index and structure index for a project.
    Ensures .story/ directory exists before writing.
    Raises exceptions on failure so callers can handle/report."""
    index_path = project_path / ".story" / "index.yaml"
    index_path.parent.mkdir(exist_ok=True)
    
    index = generate_index(project_path)
    write_index(index, index_path)
    
    structure_index = generate_structure_index(index)
    structure_path = project_path / ".story" / "structure-index.yaml"
    write_structure_index(structure_index, structure_path)
```

### 6.4 `story_index.py` Response

```python
    structure_index = generate_structure_index(index)
    structure_path = project_path / ".story" / "structure-index.yaml"
    write_structure_index(structure_index, structure_path)
    
    return json.dumps({
        "success": True,
        "message": f"Index regenerated for {index['project']['name']}",
        "index": index,
        "structure_index": structure_index
    })
```
