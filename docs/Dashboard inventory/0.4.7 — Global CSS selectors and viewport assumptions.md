| line | rule | note |

### Viewport-height usage (`100vh`)

`base.css:67` **only** — `#app { height: 100vh }`. All other `height: 100%` rules (base.css:53 `html, body`; base.css:145 `.view`) are relative to a parent, not to the viewport.

### Viewport-width usage (`100vw`)

| file | line | rule | note |
|---|---|---|---|
| `components.css` | :109 | `width: min(var(--panel-w), calc(100vw - var(--sidebar-w)));` | detail panel cap |
| `components.css` | :112 | `width: min(var(--panel-w-wide), calc(100vw - var(--sidebar-w)));` | wide detail panel cap |
| `statistics.css` | :27 | `width: min(var(--stats-panel-w), calc(100vw - var(--sidebar-w)));` | stats panel cap |

All three are `min(X, calc(100vw - Y))` — a panel whose width would exceed the viewport is capped. These are the only viewport-width assumptions in the CSS.

### `window.innerWidth` / `window.innerHeight` — tooltip clamping only (not layout)

Verified by read; no `innerWidth`/`innerHeight` used for layout.

| file | lines | usage |
|---|---|---|
| `graph/value-graph.js` | :481–482 | `if (x + w > window.innerWidth - 8) x = e.clientX - w - 16; if (y + ht > window.innerHeight - 8) y = Math.max(8, window.innerHeight - ht - 8);` — value-graph hover card stays inside the viewport |
| `panels/character-journey-tab.js` | :281, :283 | `const x = Math.min(ev.clientX + 14, window.innerWidth - el.offsetWidth - 8); … el.style.top = Math.min(ev.clientY + 14, window.innerHeight - el.offsetHeight - 8) + 'px';` — journey hover card stays inside the viewport |
| `graph/network.js` | :137 | `edgeTooltip.style.left = Math.min(params.event.clientX + 14, window.innerWidth - 220) + 'px';` — graph edge tooltip stays inside the viewport |

### `screenplay.css` — no global selectors

`src/dashboard/screenplay.css` (164 lines) has no global selectors. Every rule is `.screenplay-*` or `.fountain-*` (a class selector, or the element it targets). It is safe as-is: a scoper that prefixes every selector with `.story-root` leaves the stylesheet intact.
