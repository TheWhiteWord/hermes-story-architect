## 0.4.6 — External resources

`src/dashboard/index.html` loads exactly three external scripts, all on the
cdnjs.cloudflare.com host:

| # | line | URL | consumed by |
|---|---|---|---|
| 1 | `:9` | `https://cdnjs.cloudflare.com/ajax/libs/vis-network/9.1.9/standalone/umd/vis-network.min.js` | `src/dashboard/js/graph/network.js` — `new vis.DataSet` (`:9`, `:107`), `new vis.Network` (`:122`) |
| 2 | `:10` | `https://cdnjs.cloudflare.com/ajax/libs/js-yaml/4.1.0/js-yaml.min.js` | `src/dashboard/js/data-load.js:13` — `jsyaml.load` in `handleFileLoad` (manual-YAML path only) |
| 3 | `:16` | `https://cdnjs.cloudflare.com/ajax/libs/d3/7.9.0/d3.min.js` | `src/dashboard/js/statistics/charts.js` — `window.d3` at `:37,93,131`; the `d3` global invoked directly throughout the rest of the file |

**U4 is answered.** The three CDNs are the only external resources in the tree.

**Hard runtime dependencies.** Two of the three are hard dependencies of the old
dashboard: `window.vis` is read at `network.js:9,107,122` (`new vis.DataSet`,
`new vis.Network`), and `window.d3` is read at `charts.js:37,93,131`, with the
`d3` global called directly throughout the rest of the file. The dashboard
cannot run without them.

**js-yaml.** Used only by `data-load.js:13` (`handleFileLoad`), the manual-YAML
path. `src/dashboard/js/` has no other `yaml`/`jsyaml` references (verified).

**No fonts, images, or other hosts.** A grep for `https?://` over `src/dashboard/`
returns only the three CDNs above. The one `url(` at `value-graph.js:224` is an
internal SVG `fill="url(#uid-h)"` pattern reference, not an external resource;
there is no `@font-face` anywhere in the tree.

**Invariants this feeds.** (1) Nothing beyond these three CDNs is fetched at
runtime on the `file://` page. (2) If the port ships a vendored bundle, it must
be a bundle of exactly these three libraries, imported as ES modules from
`desktop-src/` — nothing is read from `window`. The vendored files are the
module sources; the built `plugin.js` is checked by `hermes plugins validate`
early (Phase 1 canary) because the desktop-surface lint refuses `eval` /
`new Function` even inside a bundle.

**Test that pins the d3 tag.** `tests/test_story_dashboard_integration.py:92` (`test_d3_cdn_loaded`) asserts `'d3.min.js' in dashboard_html`.
