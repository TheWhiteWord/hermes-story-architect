## 0.4.1 — Views and tabs

The dashboard is one static HTML page (`src/dashboard/index.html`, 509 lines)
that shows one view at a time. There are three independent sub-view switching
systems beside the top-level one, plus two elements that *look* like views but
are not.

### Top-level views — nine

All nine are `<div class="view" id="<name>-view">` inside `<main id="main">`
(`index.html:163`). Exactly one carries `active`; `.view { display: none }`
(`css/base.css:145`) and `.view.active { display: flex }` make that the whole
switching mechanism. `DASH.switchView` (`js/navigation.js:18`) is the only
thing that moves `active`:

```js
document.querySelectorAll('.view').forEach(v => v.classList.remove('active'));
document.querySelectorAll('.nav-btn[data-view]').forEach(b => b.classList.remove('active'));
document.getElementById(view + '-view').classList.add('active');
```

The view id **is** the nav `data-view` value, and the container id is
`'<view>-view'`. That invariant is what a port can rely on.

|---|---|---|---|---|---|---|---|---|---|

Every view is `.view-header` + `.view-body`, and **all nine** carry a
`.view-subtitle` with id `<view>-subtitle` (`index.html:169, 178, 198, 215, 226,
239, 250, 261, 270`) — none is optional. Three views also carry
`.view-header-actions`: `graph` (`:179`, Reset), `scenes` (`:199`, search),
`script` (`:271`, Statistics). The only view whose *title* is dynamic is
`story`: `#story-project-name` is set from `p.name` by `js/views/story.js:7`.

Each view's `.view-body` has its own layout rule, and they are **not** the same
rule — a port cannot style them with one selector:

| view | body rule |
|---|---|
| `story` | `css/views.css:54` |
| `scenes` | `css/views.css:2` |
| `graph` | `css/graph.css:2` |
| `values` | `css/views.css:260` |
| `script` | `css/views.css:266` |
| `locations`, `plots`, `relationships`, `worlds` | `css/views.css:135` (`.entity-list-view .view-body`) |

**Nav order is not view order.** The sidebar emits
`story, graph, relationships, scenes, locations, plots, values, worlds, script`
(`index.html:44,53,68,78,88,96,106,113,121`), which is neither the source order
nor alphabetical. A port that derives the nav from the view list must sort by
this sequence, not by array order.

**Four views carry an extra class.** `locations`, `plots`, `relationships`,
`worlds` are `class="view entity-list-view"` (`:212, :223, :236, :247`);
`css/views.css:135` gives that class its body layout. The other five are
plain `.view`. This is the only structural difference between an "entity list"
view and a plain one.

**`index.html:235`'s comment says "Worlds View" above the relationships block.**
The comment is wrong; the markup (`id="relationships-view"`, title
`Relationships`) is right. It is one of **two** `<!-- Worlds View -->` comments
in the file — the other is at `:246`, correctly above `#worlds-view` at `:247`.
Every other view has exactly one comment (`:165, :174, :194, :211, :222, :257,
:266`). The fix is the comment.

### Sub-views — three switching systems besides the top level

**1. Graph tab strip.** `graph` has one `.graph-tab`, `#tab-network`
(`index.html:184`), and one `.graph-tab-content`, `#graph-tab-network` (`:187`).
Switched by `DASH.switchGraphTab` (`navigation.js:45`), which mirrors
`switchView`'s pattern: drop `active` from every `.graph-tab` and
`.graph-tab-content`, add it to `#tab-<tab>` and `#graph-tab-<tab>`, and hide
`#graph-legend` unless `tab === 'network'`.

One tab only, so the strip is dead weight today — but the CSS
(`css/graph.css:55-77`) and the JS both already support N. A port keeps the
strip, because removing it changes the DOM the parity test compares.

**2. Values toolbar.** `values` has no HTML tab strip at all; the strip is
built by `buildValuesView` (`js/graph/value-graph.js:571-577`) into
`#values-body`:

```html
<div class="vg-toolbar">
  <div class="vg-seg"><button class="vg-tab" data-tab="story">Story</button><button class="vg-tab" data-tab="plot">Plot</button></div>
  <select class="vg-select vg-plot-only" id="vg-plot-select">…</select>
  <div class="vg-seg vg-acts" id="vg-acts"></div>
  <span class="vg-crumbs" id="vg-crumbs"></span>
  <span class="vg-hint" id="vg-hint"></span>
</div>
<div id="vg-content" class="vg-content"></div>
```

Switched by `DASH.switchValuesTab` (`value-graph.js:558`) — a different name
from the other two switchers, and it writes `state.tab` rather than toggling
classes directly. `renderValues` (`:545-556`) is what actually moves `active`
(`.vg-tab` at `:547`) and the `display` of `.vg-plot-only` (`:548`), then
draws the story or the plot chart into `#vg-content`.

Its state lives in `DASH.valueGraphState` (`value-graph.js:38`) and is the one
global the values view owns. `DASH.valueGraphLink` (`navigation.js:10`) builds
an inline `onclick` that sets `state.tab` / `state.plot` **and then** calls
`switchView('values', …)` — so a link from another view reaches this sub-view
already configured.

**3. Statistics groups.** The aside `#stats-panel` (`index.html:301`) has four
`.stats-tab` buttons with `data-group` = `overview`, `characters`, `scenes`,
`structure` (`:308-311`) and four matching `.stats-group` divs `#stats-group-<group>`
(`:318, :345, :376, :462`). Switched by `DASH.switchStatsGroup`
(`js/statistics/statistics.js:225`), same class-toggle pattern, plus a
`requestAnimationFrame` redraw of the group's chart. Only the three D3-backed
groups have charts; `structure` is static HTML (`statistics.js:48`).

`#stats-panel` is **not** opened by a view switch. It opens from the Script
view's Statistics button (`index.html:272`) through
`DASH.openStatsPanel()` (`statistics.js:11`), which also builds the script view
if it has not been built yet (`:12`) and closes the detail panel (`:28`). It
closes through `DASH.closeStatsPanel()` (`:7`). So the Statistics aside is a
sub-view of `script` in practice, and its open/closed state is the class `open`
on the aside (`css/statistics.css:15`).

### The detail panel — a tab strip, not a view

`aside#detail-panel` (`index.html:490`) is `#panel-header` / `#panel-body` /
`#panel-footer`, opened by the `open` class (`css/components.css:88`). It is
not in `<main>` and is not switched by `switchView`.

`js/panels/panel-tabs.js` turns it into a tab strip:

- Each `show*Panel` function renders the whole panel into `#panel-body`.
  `decorate(fnName, kind, idOf)` (`panel-tabs.js:131`) wraps it so that after
  the render, `mount` lifts the rendered HTML into an `overview` tab and
  appends the tabs a module registered.
- `register(kind, tabsFor)` (`:129`) files tabs per entity kind.
- Only two kinds are registered today:
  - `scene` → **Beats**, `js/panels/scene-beats-tab.js:216`
  - `character` → **Journey**, `js/panels/character-journey-tab.js:290`
- `activate(id)` (`:44`) is the switcher: it toggles `active` on `.ptab` and
  `.ptab-pane`, sets the footer, and lazily renders the pane on first visit
  (`pane.dataset.ready`).
- `memory.tab[kind]` (`:17`) remembers the last tab per kind across panels;
  `memory.wide` remembers the widen preference. `setWide` (`:24`) toggles
  `panel-wide` on the aside (`css/components.css:95`).
- `mount` always prepends `{id: 'overview', label: 'Overview'}`
  (`:106`), so every tabbed panel has at least two tabs even when a module
  registers nothing.

**The `show*Panel` set is eight, not six.** `js/panels/entity-panels.js`:
`showActPanel:27`, `showCharacterPanel:77`, `showLocationPanel:157`,
`showPlotPanel:234`, `showRelationshipPanel:314`, `showScenePanel:386`,
`showSequencePanel:525`, `showWorldPanel:567`. Two take an **object**
(`character`, `relationship`), the other six take an **id** — which is why
`decorate` takes an `idOf` argument: it is called with `args => args[0]` for
scenes (`scene-beats-tab.js:236`) and `args => args[0] && args[0].id` for
characters (`character-journey-tab.js:305`). Only `showCharacterPanel` and
`showScenePanel` are decorated, because only those two kinds have a tab module.

**`data-ent` is the cross-view navigation protocol.** A click on any element
carrying `data-ent="type:id"` inside `#panel-body` opens that entity's own
panel (`panel-tabs.js:93-94` → `openEntity` at `:117`). Types handled:
`character`, `location`, `world`, `relationship`, `scene`. Emitters:
`scene-beats-tab.js:38` (`ref.type:ref.id`), `character-journey-tab.js:183,193`
(`scene:<id>`), `entity-panels.js:20` (`scene:<id>`).

`openPanel` and `closePanel` are also wrapped (`:145-158`) — not for tabs, but
so that a panel with **no** registered tabs (location, world, relationship) still
wires the delegated `data-ent` click. Without that wrapper those panels' scene
links are dead.

**The tab strip's `active` state is per-pane, not global.** `activate` (`:51-52`)
toggles `.ptab.active` by `data-tab` and `.ptab-pane.active` by `data-pane`, and
the initial activation is `overview` unless `memory.tab[kind]` names a tab that
exists (`:111-112`). A pane renders lazily on first activation
(`pane.dataset.ready`, `:60`), and a tab declaring `redraw: true` re-renders
whenever the pane's width changes by more than 8px (`:63-75`) — both Beats and
Journey declare `redraw: true` (`scene-beats-tab.js:228`,
`character-journey-tab.js:295`).

### The Memory dialog — a modal, not a view

`div#memory-dialog` (`index.html:158`), a direct child of `#app` outside
`<main>`, opened by the `open` class (`css/components.css:310`). Built entirely
by `js/panels/memory-dialog.js`: `openMemoryDialog` (`:3`) fills
`#memory-dialog-content` from `DASH.story.story_memory`, `closeMemoryDialog`
(`:35`) removes the class.

It has its own inline escaper at `:17` — a second implementation of
`escapeHtml`, not a call to `DASH.escapeHtml`. It also closes on `Escape` via
`DASH._bindMemoryDialog` (`:41`), which is invoked once at module load (`:48`).
`_memoryDialogBound` (`:40`) has exactly one writer and one reader, both in this
file: it is a load-once guard, not shared state.

### Views with no JS of their own

`views/locations.js` (34 lines), `views/plots.js` (58), `views/relationships.js`
(57) and `views/worlds.js` (31) are pure renderers: read `DASH.story.<kind>`,
return an HTML string, assign it to their container. Their containers are
`#location-list`, `#plot-list`, `#relationship-list`, `#world-list` — all
`class="entity-grid"` (`index.html:218, 229, 242, 253`), which is what
`entity-list-view` styles.

### Dead state in `navigation.js` (recorded, not fixed here)

Three module-scoped variables and one alias are written and never read:

- `sidebarExpanded` (`navigation.js:3`) — read only by `toggleSidebar` itself.
- `currentView` (`:5`), initialised to `'graph'` while the markup's default
  active view is `story` (`index.html:166`). `DASH.currentView` (`:23`) is
  written on every switch and read by nothing.
- `DASH._origSwitchView` (`:58`) — an alias of `switchView` taken at load time,
  read by nothing in the product code.

**`DASH._origSwitchView` is pinned by a test, so it is not free to delete.**
`tests/test_story_dashboard_integration.py:73` asserts
`'DASH._origSwitchView = DASH.switchView;' in js_content`, under a docstring
that claims *"switchView is wrapped (not replaced)"*. **The docstring is false:
nothing wraps `switchView`.** The only wrapper in the file is the alias at
`:58`, and `switchView` is defined at `:18` — the alias points at the final
function and is never called. The test guards a behaviour that does not exist.
