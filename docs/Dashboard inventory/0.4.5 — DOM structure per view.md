## 0.4.5 — DOM structure per view

For each of the nine views, record: the container id, the elements the JS
fills, and the classes the CSS expects.

The nine views, in `index.html` order, with their container, the module that
fills them, and the CSS file that styles them:

|| view id | container | class(es) | view-body / id filled | filling module | CSS |
|---|---|---|---|---|---|
| `story` | `#story-view` | `view active` | `#story-body` | `views/story.js` | `views.css:54` |
| `graph` | `#graph-view` | `view` | `#graph-tab-network` | `graph/network.js` | `graph.css:2-8` |
| `scenes` | `#scenes-view` | `view` | `#scene-list` | `views/scenes.js` | `views.css:2-6` |
| `locations` | `#locations-view` | `view entity-list-view` | `#location-list` | `views/locations.js` | `views.css:135-140` |

| `worlds` | `#worlds-view` | `view entity-list-view` | `#world-list` | `views/worlds.js` | `views.css:135-140` |

Notes:

- Four views carry the `.entity-list-view` class: locations, plots, relationships,
  worlds (index.html:212, 223, 236, 247). `.entity-list-view .view-body` is
  `flex:1; overflow-y:auto; padding: var(--gap)` (views.css:135-139). The other
  five views use the plain `.view-body` rule.
- The `script` `.view-body` is **not** a plain flex column: it is
  `display:flex; justify-content:center` (views.css:266-272). 
- The container at `index.html:236` sits under a comment `<!-- Worlds View -->`;
  the real Worlds view is at `:247` (`#worlds-view`). The comment is wrong, the
  markup is right.
